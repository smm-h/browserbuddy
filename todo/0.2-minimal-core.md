# BrowserBuddy 0.2 — minimal core (the inversion, stripped to what users will feel)

This is the **executable subset** of the full 0.2 inversion design. The complete, locked design record — every decision, every rejected alternative, the full feature set — lives verbatim in `todo/.defer/0.2-inversion-extension-first-architecture.md`. This file is the build spec: what we actually ship in the 0.2 arc, and what we deliberately hold back until a real need appears.

The cut was made on one question: *will a user care?* Replay engines, unified Action models, side-panel GUIs, multi-install identity, and a brand-new MCP revision are all real ideas — but agent-mediated replay already works today, and the rest serve needs nobody has demonstrated yet. What users (and honesty) actually demand is: attach securely, don't lie about what you can't see, and don't lose the thread across restarts.

## In scope (build this)

1. **Transport #6 — browser-spawned native host serving loopback HTTP MCP.**
   - Extension `chrome.runtime.connectNative(...)`; the browser spawns the host. The host (a normal OS process) binds `127.0.0.1:<ephemeral>` and serves Streamable-HTTP MCP behind a bearer token. Claude dials that endpoint.
   - The host writes Claude's MCP config itself (live port + token) so setup is one gesture.
   - Extension never binds a socket; the host is always the listener. This fixes both the security defect (unauthenticated `ws://8590` today) and the lifetime inversion (always-on side now owns the endpoint).
   - Host absent → precise, actionable hard error. Never a silent WebSocket fallback.

2. **Move semantics into the extension; the external component becomes a domain-blind pipe.**
   - Event store, history, demo cleaning, MCP tool definitions + dispatch move into the extension. The host/npm artifact carries no browser vocabulary. A tripwire test (mirroring the stdout-purity tripwire) asserts zero product vocabulary in the pipe.
   - Staging is allowed (swap transport first, hollow out after) as long as the end state is extension-owns-semantics.

3. **Unknown-message policy fix (repairs a live "absence must be observable" violation).**
   - Unknown **event** → recorded with an explicit `unknown` marker (nothing lost). Unknown **RPC method** → hard error naming the method.

4. **Persistent, extension-owned seq.** Monotonic per install, survives restarts of everything, so `browser_observe` `sinceSeq` is stable across sessions ("everything since I last looked" works across days).

5. **Minimal consent surface (plain options page, no side panel).** Because history now persists in the extension, these are owed:
   - mandatory first-run observation-mode choice (volatile-only / persist-when-armed / always-persist) — no pre-selected default;
   - one-click observation pause (badge-reflected);
   - never-observe origin list;
   - delete-all and delete-last-N-minutes.
   - No `storage.sync`, no incognito operation.

6. **New invariant — "absence must be observable"** — recorded in `docs/ARCHITECTURE.md` and enforced where cheap (the `unknown` markers above; hard refusals on mismatch).

7. **Reserve the `replay` actor enum value** in the schema + `docs/PROTOCOL.md` (one line, no behavior) so it is never reused when the replay engine eventually lands.

## Deferred (in `.defer` record — do NOT build until a real need shows)

- Deterministic replay engine, run journal, `on_failure` policies, healing events — agent-mediated replay already covers the demonstrated need.
- Unified Action model, parameterization, locator bundles, `action_*` MCP surface.
- Side-panel GUI and the history-browser timeline (options-page controls only, for now).
- Multi-install identity (UUIDs, labels, discovery directory, tool `target` param). Keep only the trivial guard: second attach → hard error naming both.
- MCP `2026-07-28` adoption (`server/discover`, `subscriptions/listen`, MRTR-for-lockstep) — keep the current handshake until a client forces the change.
- Optional host permissions + `not_observed` markers — land with the store submission, not before.
- Protocol integer + hash-derivation + store-forced skew policy — tie to store submission (skew only exists once the store controls one artifact's clock).
- Store submission (CWS + AMO), the §8 capability request, `#7`/`#8-relay` transports.

## Sequencing

Dependency order, verify-before-fan-out: the transport (item 1) has genuine runtime unknowns (MV3 service-worker lifetime vs. a browser-spawned listener; whether Claude Code attaches to the host's loopback HTTP MCP) — spike and confirm these for real before building the cross-platform installer and the semantics move on top of them. Items 3, 4, 7 are low-risk and land early. Item 5 travels with item 2 (persistence owes consent). Release **once, at the very end** of the arc.

When the build is complete and verified, move this file to `todo/.done/`.
